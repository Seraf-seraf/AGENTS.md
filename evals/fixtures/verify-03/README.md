# Отправка операции

`SubmissionService(database, dependency).submit(key)` отправляет операцию во
внешнюю зависимость. `database` — путь к SQLite-файлу; `dependency` — вызываемый
объект, принимающий ключ и возвращающий строку-квитанцию. Сеть для проекта не
нужна. Зависимость можно заменить управляемой функцией в тестах.

## Контракт

- Рассматриваются последовательные вызовы. Один непустой строковый ключ
  обозначает одну операцию. Конкурентные вызовы и авария процесса внутри
  внешнего вызова не входят в задачу.
- На один вызов `submit` разрешены максимум **две** попытки обращения к
  зависимости. После `TemporaryFailure` следующая попытка выполняется в этом
  же вызове, пока его бюджет не исчерпан. Эти отказы возникают до внешнего
  эффекта.
- Если обе попытки завершились временным отказом, вернуть
  `{"status": "retryable", "receipt": null}`. Это разрешение клиенту снова
  вызвать `submit` с тем же ключом. Новый вызов получает собственный бюджет
  двух попыток, в том числе после пересоздания сервиса с тем же файлом БД.
- Успешный результат — `{"status": "succeeded", "receipt": <квитанция>}`.
  Результат сохраняется. Повтор с тем же ключом возвращает ту же квитанцию
  без нового вызова зависимости, в том числе из нового экземпляра сервиса.
- `PermanentFailure` завершает операцию сразу: результат
  `{"status": "permanent", "receipt": null}` сохраняется. Повтор с тем же
  ключом возвращает его без обращения к зависимости. Этот отказ также
  возникает до внешнего эффекта.
- Разные ключи независимы. Схема SQLite и способ ведения счётчиков — внутренние
  детали; менять публичную сигнатуру и значения результатов не требуется.

Штатная проверка: `python3 -m unittest discover -v`.
