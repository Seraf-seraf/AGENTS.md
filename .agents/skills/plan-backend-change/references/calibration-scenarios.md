# Калибровочные сценарии планирования

Использовать при изменении навыка. Проверять созданный план на исходной задаче, а правила исполнения — отдельным запуском исполнителя с этим планом в изолированном проекте. Отсутствие ошибок в тексте не доказывает поведение исполнителя.

| Ситуация | Наблюдаемый критерий |
| --- | --- |
| Небольшая доработка по готовому исследованию | Один достаточный этап с реальными путями и командами; нет нового исследования и искусственных слоёв. При подготовке плана исходники и индекс задачи не изменены. |
| Три этапа, назначен только второй | Контекст отделён от действий; исполнитель завершает второй этап и не пишет код третьего. |
| Поручены два зависимых этапа | Оба выполнены в заданном порядке без лишнего подтверждения между TDD-шагами; остановка после второго. |
| Нужный сервис уже существует | План указывает USE или конкретный MODIFY, не CREATE дубликата из справочного описания. |
| Неизвестен существенный контракт библиотеки | Без поручения исследования вопрос раскрыт как препятствие; по поручению есть ограниченный исследовательский этап с методом и проверяемым выводом. Зависимая реализация не опирается на выдуманный API. |
| Параллельная задача меняет несвязанный код | Нет требования исходного SHA или блокировки от любой смены HEAD. Общие файлы и владение stage обозначены при пересечении. |
| Этап выполнен частично или закоммичен | Продолжение сохраняет подтверждённую работу; повтор не дублирует маршруты, классы, миграции или коммит. |
| В разрешённом файле есть чужие hunks | Итоговые staged diff и коммит содержат только порученные изменения; allowlist путей не принимается за доказательство чистоты содержимого. |
| Недоступна обязательная проверка | План называет среду и ожидаемое свидетельство; исполнитель отмечает проверку незавершённой, не подменяет её зелёным несвязанным suite. |
| Рефакторинг, документация или исследование | Проверка соответствует результату; отсутствуют искусственный RED и фиктивный коммит при отсутствии diff. |

Оценивать отдельно структуру плана, техническое содержание и реально наблюдавшиеся действия исполнителя. Сравнивать с исходными требованиями и состоянием проекта, а не с единственной ожидаемой формулировкой. Прогон конкретной модели в одной среде не означает универсальной гарантии остановки или качества.
