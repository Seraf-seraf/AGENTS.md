# Калибровка оценки изменений

Материал для проверки и уточнения навыка, не обязательный аудит каждого проекта. Условия ниже — специально заданные примеры, а не факты о каком-либо репозитории. При изменении условий оценка может измениться.

Для проверки поведения агента давать ему условие без ожидаемого ответа и сравнивать решение с критериями. Чтение этой таблицы и проверка текста навыка не являются выполненным испытанием модели. Успех определяется обоснованием, границами и выбранными проверками, а не совпадением слов или числовой оценки.

| Сценарий и заданные условия | Ожидаемое решение | Недопустимое решение |
| --- | --- | --- |
| Внутренний чистый вспомогательный компонент переименовывается; все вызовы известны, поведение и публичный API не меняются, локальное покрытие достаточно. | Низкая сложность; минимальная глубина, проверка вызовов и относящегося покрытия. | Обязательный UX-аудит, браузерный E2E или новая архитектура. |
| Одна строка меняет проверку владельца документа; ошибочное разрешение раскрывает чужие данные. | Локальная сложность, высокий риск; углублённая проверка разрешения и отказа на затронутых путях, а не аудит всех систем. | Минимальная проверка только потому, что объём изменений мал; отключение авторизации для удобства. |
| API-фильтр затрагивает список архивных заказов; контракт включает архивные заказы, но технический признак «активен» исключает их. | Целевая проверка бизнес-условия и результата потребителя; не выдавать неполные данные за отсутствие записей. | Применить один технический фильтр ко всем спискам без проверки их контрактов. |
| Запись платежа могла пройти, но ответ потерян; повтор с новым идентификатором может повторить списание. | Углублённый анализ неизвестного исхода и безопасного повтора; проверить принятый механизм идемпотентности или сверки результата. | Назвать истечение времени ожидания доказанным отказом и повторять побочный эффект вслепую. |
| Необязательная аналитика недоступна; по контракту это не препятствует сохранению заказа, данные заказа сохраняются независимо. | Проверить локализацию отказа и сохранение заказа; расширять проверки только для реальных зависимостей. | Заблокировать оформление заказа или объявить аналитику успешной. |
| Отмена CLI-задачи с общим ресурсом разрешена; запуск следующей допустим только после подтверждённого освобождения. | Проверить цепочку отмена → очистка ресурсов → допустимый повтор и независимую команду чтения; без UI-тестов. | Снять блокировку до освобождения либо считать бессрочную блокировку достаточным восстановлением. |
| Для малой текущей нагрузки предложен брокер «на будущее»; существующий механизм обеспечивает все заданные гарантии. | Необходимость нового механизма не подтверждена; описать достаточное решение и условие пересмотра. | Добавить брокер, новые сценарии и проверки только ради предполагаемого роста. |
| Пользователь согласовал дорогую миграцию данных; обязательная интеграционная проверка недоступна в текущей среде. | Сохранить объём, отдельно оценить реализацию, неизвестные и стоимость проверки; отметить непроверенную границу. | Самовольно убрать миграцию, отменить проверку или выдать локальную имитацию зависимости за полную приёмку. |

Во всех сценариях оценка должна быть выполнима без подключения систем учёта и без создания их задач. Не вводить обязательные часы, баллы и отдельные документы. Повторная оценка нужна при новых существенных данных, а не при передаче результата между навыками.

## Выбор предмета и границы работы

| Запрос и условия | Ожидаемый результат |
| --- | --- |
| «Оцени сложность и риски», код и условия доступны | Оценка с основаниями; нет реализации, формального плана или автоматического обращения к трекеру. |
| «Как лучше вынести отправку в очередь», решения ещё нет | Выбор достаточного решения по коду, существенные отказы и неизвестные; без обязательного отдельного ревью и плана. |
| «Проверь готовое решение; только ошибки» | Подтверждённые несоответствия; недоказанные риски не выданы за дефекты, отсутствие замечаний допустимо. |
| «Составь план по готовым решениям» | Ведущий результат — план; общие факты и готовая оценка не исследуются заново без оснований. |
| «Добавь поле и фильтрацию; подготовь изменения» | Порученная реализация с проверкой, без обязательного отдельного плана и отчётов разбора. |
| Узкий вопрос о поле после уже выполненного анализа | Краткий ответ из известного контекста; не начинается новый полный разбор. |
| Пользователь отдельно поручил оценку, план и реализацию | Все порученные результаты в заданных границах; правило одного результата не отменяет составной запрос. |
| Существующие эндпоинты нарушают изоляцию данных, новых модулей нет | Ревью сохраняет проверку доступов и контрактов; отсутствие нового модуля не исключает архитектурный разбор. |
