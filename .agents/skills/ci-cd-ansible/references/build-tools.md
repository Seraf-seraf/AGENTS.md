# Makefile, Docker и shell

Применять только к изменяемому инструменту. Не добавлять инструмент в проект ради выполнения этих правил.

## Makefile

- Существующий Makefile использовать как основной интерфейс типовых операций. Сначала искать готовую цель; новую добавлять только для повторяемого сценария.
- Цели без файлового результата объявлять `.PHONY`.
- Не прятать в цели необратимые операции и изменения окружения пользователя: назначение должно быть явно видно из имени, а выполнение — разрешено задачей.

## Docker

- При создании или изменении сборки image предпочитать multi-stage build, небольшой runtime image, непривилегированного пользователя, `.dockerignore` и явно зафиксированные версии базовых образов. Изменение Compose wiring не требует попутной перестройки Dockerfile.
- Не помещать секреты в image, Dockerfile, build arguments или репозиторий. Конфигурацию передавать во время запуска.
- При изменении image проверять точный `CMD`/entrypoint, production-зависимости, минимальный запуск и затронутое health behavior. При подключении готового image проверять его интеграцию через существующий Compose и runtime-конфиг; не компилировать заново согласованную готовую поставку.

## Shell-скрипты сборки и доставки

- Использовать shell, заявленный средой и проектом. Для POSIX `sh` сохранять совместимый синтаксис и `set -eu`; не навязывать POSIX другим языкам или runtime.
- Заключать expansion переменных в кавычки; обязательные входы проверять до мутаций, для обязательных непустых переменных использовать `${VAR:?}`. Ожидаемые ненулевые коды обрабатывать явно.
- Передавать внешние входы через аргументы или документированные переменные окружения; не полагаться на случайные локальные значения.
- Выполнить `shellcheck` для изменённых скриптов с учётом их диалекта и, когда применимо, безопасный запуск с минимальными test inputs. Если инструмент недоступен, сообщить это ограничение.
- Исключение lint-правила сопровождать комментарием с технической причиной и областью действия.
