# Ограниченное исполнение плана

## Выбрать режим Git

Для каждого этапа выбрать один режим по действующему поручению пользователя. Указать выбранный режим в этапе. Один раз включить в план таблицу режимов и правила выбора, чтобы исполнитель мог применить новое поручение пользователя.

Фраза «без коммита» запрещает коммит. Запись в индекс при этом требует отдельного поручения. Поручение создать коммит включает необходимую подготовку индекса. Поручение отправить конкретные ещё не закоммиченные изменения включает создание нужных коммитов. При отправке готовых коммитов сохранить индекс и рабочее дерево.

Если порученное действие требует коммита, а пользователь запретил коммит или запись в индекс, выполнить независимую работу. Уточнить разрешение до записи в индекс, коммита и отправки.

| Режим | Условие и действие |
| --- | --- |
| **Только рабочее дерево** | Запись в индекс запрещена либо по поручению не требуется ни запись в индекс, ни создание коммита. Выполнить назначенные изменения и проверки. Сохранить индекс и HEAD. В командах чтения, которые могут обновить индекс, отключать необязательные блокировки, например `git --no-optional-locks status --short`. |
| **Индекс без коммита** | Пользователь поручил добавить изменения этапа в индекс. Запись в индекс разрешена, коммит по поручению не нужен или запрещён. После проверок добавить только порученные изменения. Проверить состав индекса и сохранить HEAD. |
| **Локальный коммит** | По поручению нужно создать коммиты изменений этапа. Запретов на коммит и запись в индекс нет. После проверок создать коммиты по независимым причинам и проверить их содержимое, состояние индекса и рабочего дерева. |

Если пользователь изменил объём разрешённых действий после составления плана, перед работой с Git выбрать режим заново. Проверить результат по новому режиму и сообщить о расхождении с планом. При отсутствии изменений этапа сохранить индекс и HEAD в любом режиме.

## Включить правила ограниченного исполнения

Поместить в раздел правил самого плана, чтобы они были доступны исполнителю без этого навыка:

- По умолчанию один запуск выполнения охватывает один назначенный этап. Несколько этапов выполнять, если пользователь явно поручил этот объём; после последнего остановиться. Общее описание и последующие этапы не разрешают начинать их. При неясном назначении этапа уточнить его до изменений.
- Внутренние шаги назначенного этапа последовательно выполнить до его конца; не требовать нового подтверждения между RED и GREEN. Проверки этапа не должны требовать ещё не порученной реализации будущих этапов.
- Разрешать адаптацию локальных деталей без изменения согласованных контрактов и ответственности. Изменение бизнес-правила, публичного контракта, модели данных, зависимостей или области требует пересмотра относящейся части плана. Несвязанные параллельные изменения или новый HEAD сами по себе не блокируют работу; сверять затронутые предпосылки.
- При порученном исправлении замечаний использовать [архитектурные критерии обработки замечаний](../../analyze-change/references/architecture.md#подтвердить-каждое-замечание).
- Для повтора и продолжения сопоставить фактическое состояние с началом и концом назначенного этапа. Готовое проверить без дублирования; частично выполненное продолжить с недостающего действия. Сохранять зафиксированные пути, имена миграций и контрактов; не генерировать новый комплект при каждом запуске. При отсутствии относящихся изменений не создавать пустой или повторный коммит.
- При параллельной записи использовать отдельные рабочие копии или назначить одного владельца общего индекса и коммитов.
- Если режим разрешает запись в индекс, добавлять изменения точными путями. В смешанных файлах выбирать только фрагменты этапа. Не использовать `git add .` и `git add -A`. При добавлении в индекс без коммита учитывать уже добавленные изменения своих этапов. Если свои фрагменты нельзя выделить безопасно, сохранить соответствующую часть индекса и сообщить о препятствии.
- При подготовке коммита проверить точный кандидат по навыку `prepare-commit`. Обычный коммит допустим, только если весь индекс соответствует кандидату. Если кандидат нельзя изолировать, остановить фиксацию и сообщить причину.
- Сохранить исходное содержание чужих staged-фрагментов в индексе и чужих unstaged-фрагментов в рабочем дереве. После коммита сверить его diff с кандидатом. Проверить каждый набор чужих фрагментов в том состоянии, где он находился до коммита.
- Каждый готовый коммит этапа по одной семантической причине включает относящиеся код, постоянные тесты и необходимые контракты вместе; следует после проверок. Коммит не разрешает следующий этап, отправку изменений в удалённый репозиторий, создание PR или развёртывание. Уже данное пользователем разрешение учитывать без повторного запроса.
- Если поручен `push`, перед отправкой сверить весь исходящий диапазон с поручением. Сравнивать с фактической ревизией удалённой ветки или с согласованной базой новой ветки, уже доступной в удалённом репозитории. Если в диапазоне есть несвязанные коммиты, сначала безопасно выделить разрешённый набор. После отправки проверить ревизию удалённой ветки.
