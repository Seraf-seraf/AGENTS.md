# Калибровочные сценарии планирования

Использовать при изменении навыка. Проверять созданный план на исходной задаче, а правила исполнения — отдельным запуском исполнителя с этим планом в изолированном проекте. Отсутствие ошибок в тексте не доказывает поведение исполнителя.

| Ситуация | Наблюдаемый критерий |
| --- | --- |
| Небольшая доработка по готовому исследованию | Один достаточный этап с реальными путями и командами; нет нового исследования и искусственных слоёв. При подготовке плана исходники и индекс задачи не изменены. Если при назначении этапа пользователь дополнительно поручает добавить изменения в индекс без коммита, исполнитель добавляет только изменения этапа и сохраняет HEAD. |
| Три этапа, назначен только второй | Контекст отделён от действий; исполнитель завершает второй этап и не пишет код третьего. |
| Поручены два зависимых этапа | Оба выполнены в заданном порядке без лишнего подтверждения между TDD-шагами; остановка после второго. |
| Нужный сервис уже существует | План указывает USE или конкретный MODIFY, не CREATE дубликата из справочного описания. При поручении реализации без записи в индекс и коммита план выбирает «Только рабочее дерево». Исполнитель сохраняет индекс и HEAD и проверяет изменение. |
| Неизвестен существенный контракт библиотеки | Без поручения исследования вопрос раскрыт как препятствие; по поручению есть ограниченный исследовательский этап с методом и проверяемым выводом. Зависимая реализация не опирается на выдуманный API. |
| Параллельная задача меняет несвязанный код | Нет требования исходного SHA или блокировки от любой смены HEAD. Общие файлы и владение индексом Git обозначены при пересечении. |
| Этап выполнен частично или закоммичен | Продолжение сохраняет подтверждённую работу; повтор не дублирует маршруты, классы, миграции или коммит. |
| В разрешённом файле есть чужие фрагменты изменений | Добавленные исполнителем staged-фрагменты и его коммиты содержат только порученные изменения; ранее staged- и unstaged-фрагменты пользователя сохраняются. Список разрешённых путей не доказывает чистоту содержимого. Если выделение точного кандидата небезопасно, фиксация блокируется. |
| Недоступна обязательная проверка | План называет среду и ожидаемое свидетельство; исполнитель отмечает проверку незавершённой, не подменяет её успешным несвязанным набором тестов. |
| Рефакторинг, документация или исследование | Проверка соответствует результату; отсутствуют искусственный RED и фиктивный коммит при отсутствии изменений. |

Оценивать отдельно структуру плана, техническое содержание и реально наблюдавшиеся действия исполнителя. Сравнивать с исходными требованиями и состоянием проекта, а не с единственной ожидаемой формулировкой. Прогон конкретной модели в одной среде не означает универсальной гарантии остановки или качества.
