# Совместимость и границы подтверждения

Проверка относится к версии `software-engineering` **0.9.0**, состоянию исходников и среде, записанным в отчёте конкретного прогона. Дата проверки документации и доступной среды — **2026-11-22**. Совпадение формата файлов ещё не подтверждает выполнение задачи моделью.

## Что именно считается проверенным

| Уровень | Свидетельство | Что оно подтверждает |
| --- | --- | --- |
| Формат | Чтение манифеста, YAML и Markdown; проверка относительных ссылок | Пакет имеет ожидаемую структуру, а его инструкции доступны по указанным путям. |
| Загрузка | Среда показывает навык и позволяет прочитать его `SKILL.md` и нужный справочник | Клиент обнаруживает конкретную версию материалов. |
| Исполнение | Сохранены задача, версия клиента, модель, trace, ответ, изменения и результаты команд | Конкретный сценарий выполнен в указанной среде. |
| Поведение | Независимые проверки артефактов и отдельная оценка по скрытым критериям | Выполнены проверяемые требования конкретного испытания. |

Успешный тест runner проверяет сам runner. Он не доказывает прохождение 26 сценариев моделью. Проверка одного сценария не распространяется на остальные навыки, версии клиента или модели. Статус `NEEDS_REVIEW` означает незавершённую смысловую оценку; отсутствие обязательной среды нельзя превращать в `PASS`.

## Подключение инструкций

### AGENTS.md и навыки — разные части поставки

Корневой `AGENTS.md` подключается отдельно от плагина. Его можно использовать как общие или проектные инструкции: он находит навыки по имени в доступном каталоге, без зависимости от относительного пути к `.agents/`. Подробные инженерные правила находятся внутри соответствующего навыка. Для перенесённых из прежнего `AGENTS.md` общих норм предусмотрены прямые резервные ссылки: отсутствие навыка или старая версия плагина не отменяют требования прочитать полные материалы.

Без сети эти три справочника должны быть доступны локально: `analyze-change/references/technical-judgment.md`, `verify-change/references/engineering-rules.md` и `verify-change/references/verification-workflow.md`. Установленный актуальный плагин или локальная копия репозитория уже содержат их. Один изолированный `AGENTS.md` без сети и справочников не содержит полного текста перенесённых норм. Это ограничение поставки нужно назвать явно; недоступные инструкции нельзя считать применёнными.

В Codex инструкции собираются из глобального и проектного уровней; более близкие к рабочему каталогу файлы уточняют более общие. Клиент выбирает не более одного файла инструкций на уровень каталога, включая приоритет `AGENTS.override.md`. Лимит объединённого текста задаётся `project_doc_max_bytes`, по умолчанию — 32 KiB. Это лимит инструкций проекта, а не общий лимит всех навыков. [Официальная документация Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

В ChatGPT и Codex в начальный каталог попадают имя и описание навыка. Полный `SKILL.md` читается при его выборе, а тематические справочники — по явно указанному условию. Поэтому уменьшение тела `SKILL.md` снижает объём загрузки при активации навыка; оно не означает, что все прежние тела навыков раньше всегда находились в контексте. [Официальная документация навыков](https://learn.chatgpt.com/docs/build-skills).

### Claude Code

По текущей документации Claude Code читает `AGENTS.md` напрямую с версии `2.1.277`, если в рабочем каталоге и выше нет `CLAUDE.md` или `CLAUDE.local.md`, меняющих выбор инструкций. Для версий и сессий, в которых это не поддерживается, предусмотрен импорт `@AGENTS.md` из `CLAUDE.md`. Это описание механизма клиента, не результат испытания данного репозитория. Перед использованием нужно проверить фактическую загрузку и отдельно способ установки навыков. В текущую поставку адаптер Claude Code не добавлен. [Официальная документация Claude Code](https://code.claude.com/docs/en/memory#agentsmd).

## Что воспроизводит набор испытаний

[Набор `evals/`](../evals/README.md) сопоставляет 16 сценариев разбора и 10 сценариев планирования с конкретными задачами и небольшими проектами. Кандидат получает задачу, проект и текущие инженерные инструкции. Эталонные критерии, проверки результата и прежние калибровочные таблицы с ожидаемыми ответами не входят в его рабочее дерево. Исполнение и оценка выполняются раздельно.

Артефакты прогона должны позволять установить исходный commit и изменённое состояние инструкций, версию плагина, клиент и модель, параметры запуска и лимиты, назначенный этап, ответ, фактические команды и изменения файлов. Для планирования сохраняется передача созданного плана отдельному исполнителю. Название модели само по себе не делает результаты воспроизводимыми: фиксируются также исходные материалы и настройки запуска.

Runner создаёт отдельные каталоги задач и сохраняет свидетельства вне них. Это организационная изоляция данных оценки; она не заменяет системную песочницу и сетевые ограничения среды агента. Пользовательский адаптер отвечает за фактические разрешения запускаемого клиента. Испытания рассчитаны на локальные фикстуры, без производственных учётных данных и внешних публикаций.

Для версии 0.9.0 сохранён [отчёт фактических проверок](verification-0.9.0.md): 43 проверки инфраструктуры и два отдельно оценённых облачных образца с точными хешами входных инструкций. Эти образцы использовали рабочий снимок до последних адресных исправлений ссылок; граница переноса результата на выпуск указана в отчёте.

## Как подтвердить новую среду

1. Зафиксировать версию клиента, ОС, модель, версию плагина и revision исходников; проверить доступные разрешения и способ подключения инструкций.
2. Проверить обнаружение одного навыка и чтение относящегося к задаче справочника. Убедиться, что общий `AGENTS.md` также подключён.
3. Выполнить нужные сценарии через доступный адаптер по [инструкции runner](../evals/README.md), сохранив исходные trace и артефакты. Отсутствие адаптера или авторизации записать как ограничение, не как успешную проверку.
4. Завершить независимую смысловую оценку и проверить наблюдаемые результаты. В отчёте назвать реально выполненные case ID и оставшиеся непроверенные сценарии.
5. Дополнить таблицу среды точной версией и ссылкой на сохранённое свидетельство. Не переносить результат автоматически на другие версии или модели.

В этой поставке нет хуков. Проверки запускаются явно через runner и штатные команды проверяемого проекта; установка плагина не подключает выполнение скриптов к событиям клиента.
