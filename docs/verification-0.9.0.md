# Проверка версии 0.9.0

Дата: **2026-11-22**. База сравнения до текущего рефакторинга — версия **0.8.1**, commit `6847dbaa1b00bb8a359b3a190de7127a4ae41547`. Проверки относятся к конкретным исходникам и средам, перечисленным ниже.

## Сохранность подробных правил

Независимая проверка содержания и маршрутизации подтвердила сохранение всех **21 перенесённого раздела**, включая конкретные ограничения, исключения и таблицы. Все **926 исходных непустых строк Markdown** учтены после пересчёта ссылок и одного исправления навигации. Обе прежние таблицы калибровочных сценариев побайтно совпадают с базой. [Карта прежних и новых мест](instruction-layout.md) содержит полное сопоставление.

В сравнении целых разделов допускается только изменение адреса относительной ссылки и явно описанная замена слов «правила из следующего раздела» на ссылку `execution-rules.md`. Остальной текст перенесённых разделов сравнивался полностью. Отдельное смысловое ревью проверяло, что условия загрузки ведут к полным нормам до соответствующего действия.

В ходе этого ревью исправлены три разрыва навигации: источник норм при отдельном AGENTS или старом плагине, условие их чтения при проверке существующего решения и отсылка к бывшему следующему разделу планировщика. Для общих норм предусмотрены три прямых резервных URL. Изолированный AGENTS без сети и локальных справочников не объявляется эквивалентом прежнего самодостаточного файла; точные условия перечислены в [совместимости](compatibility.md).

## Исполняемый набор и проверки инфраструктуры

**26 сценариев** сопоставлены с исходными условиями: `analyze-01`…`analyze-16`, `plan-01`…`plan-10`. Связь включает путь исходной таблицы, номер сценария, строку и полный текст условия. Для всех десяти сценариев планирования предусмотрены отдельные этапы планировщика и исполнителя.

Команда проверки:

```bash
python3 -m unittest discover -s evals/tests -q
```

Результат: **43 теста прошли** — 29 проверок runner и 14 проверок набора. Среда: Linux, Python `3.12.14`, Git `2.56.1`. Также проверены `runner.py list`, синтаксис 56 Python-файлов фикстур и встроенных проверок, все шесть навыков стандартным валидатором и `git diff --check`.

Проверки различают правильный и неверный фильтр, использование существующего сервиса и создание дубликата, собственный Git-фрагмент и ошибочное включение чужого изменения. Runner проверен на timeout, остановку дочерних процессов, ограничения вывода, отсутствующий output, ненулевой exit code, изменение инструкций, поддельные цитаты, неполное и некорректное решение judge. Повторный отказ запуска не перезаписывает завершённый опыт; новая невалидная оценка заменяет прежний PASS на ERROR.

Процессы кандидатов и judge в этих тестах — тестовые двойники. **43 успешных теста инфраструктуры не означают 26 успешных запусков модели.**

## Реальные облачные образцы

Два одиночных сценария выполнены свежими облачными агентами. Каждый кандидат получил только задачу, рабочее дерево и скопированные инструкции; исходные калибровочные ответы и rubric были исключены. Ответ оценивал другой агент, которому передавались скрытые критерии и сохранённые свидетельства. Runner самостоятельно проверил неизменность файлов и индекса.

| Сценарий | Наблюдаемый результат | Оценка |
| --- | --- | --- |
| `analyze-03` | Установлено, что операционный флаг `active` исключает неудалённые архивные заказы и нарушает состав экспорта; предложены проверки результата потребителя. | PASS по трём критериям. [Свидетельства](evidence/0.9.0/analyze-03.json). |
| `analyze-16` | Установлены две достижимые утечки между tenant в списке и скачивании вложения; корректный `get_document` не объявлен дефектным. | Сначала NEEDS_REVIEW из-за недостатка фактических результатов, затем PASS после независимого воспроизведения. [Обе оценки и свидетельства](evidence/0.9.0/analyze-16.json). |

Это режим **`external_record`**, а не автоматический Codex CLI. Инструмент облачных агентов не предоставил точный API ID унаследованной модели или машинный журнал их tool calls. Эти значения не выдумывались. Заявления кандидатов о запущенных тестах не использовались как доказательства запуска. В `analyze-16` дополнительная команда проверяющего независимо воспроизвела поведение фикстуры; она не доказывает историю действий кандидата.

Образцы выполнены на рабочем снимке 0.9.0 до последнего исправления резервных ссылок AGENTS и навигационной ссылки планировщика. Хеши точных входных файлов сохранены в свидетельствах. [Два отличающихся файла снимка](evidence/0.9.0/tested-instruction-delta.json) позволяют восстановить именно использованные инструкции; остальные скопированные файлы совпадают с выпуском. После этих адресных исправлений повторно проверены содержание и маршрутизация, но новый модельный прогон не заявляется. Успех образцов не распространяется на остальные 24 сценария или другие модели.

## Codex CLI: подтверждённое ограничение среды

Проверен клиент `codex-cli 0.172.0-alpha.2`. Авторизация ChatGPT присутствовала, параметры адаптера сверены с локальным `codex exec --help`. Два минимальных вызова с запросом модели `gpt-6-luna`, effort `low`, завершились **до первого события модели или инструмента**, exit code `1`:

```text
Error: failed to initialize in-process app-server client: Read-only file system (os error 30)
```

JSONL пуст, ответ модели не получен. Это ошибка инициализации среды. Исполнение 26 сценариев через Codex CLI и качество запрошенной модели этим запуском не проверены. HOME, CODEX_HOME, авторизация и глобальная конфигурация не менялись. После подтверждения ограничения дополнительные модельные попытки не выполнялись.

Claude Code в доступной среде отсутствовал. Его инструкции изучены по официальной документации, но загрузка пакета и выполнение задач не проверялись. Полная матрица — в [совместимости](compatibility.md).

## Поставка плагина

Существующий личный плагин обновлён с `0.8.1` до `0.9.0`, с сохранением его идентичности, аудитории и представления. После обновления все **40 файлов шести навыков** прочитаны из опубликованного выпуска и побайтно сопоставлены с архивом; оба манифеста сопоставлены как JSON и совпадают по значениям. В архиве 42 файла, включая 14 новых справочников; runner, его фикстуры, marketplace и хуки в пакет не входят.

Каталог текущей облачной сессии после публикации продолжил возвращать старый `verify-change` и локатор версии `0.8.1`, в том числе при явном чтении cloud-источника. Это отдельно отмечено от успешного обновления опубликованного пакета. Новая версия не объявляется активированной внутри уже открытой сессии; требуется проверить её загрузку после обновления подключения. Кеш клиента вручную не редактировался.
