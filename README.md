# Backend Engineering

Плагин `backend-engineering` для инженерных задач: определить результат и границы, выбрать минимальное решение, проверить реальное поведение и завершить работу без лишнего расширения. Инструкции и итоговые ответы — на русском.

Общие правила находятся в [AGENTS.md](AGENTS.md): границы задачи, выбор решения, проверки, завершение работы и условия применения навыков. Плагин содержит четыре специализированных навыка. Настройки моделей и разрешения клиента не поставляются.

## Навыки

| Навык | Когда применять |
| --- | --- |
| `review-backend-architecture` | Проверка границ и зависимостей; замечания с доказательствами и минимальным исправлением. |
| `verify-backend-change` | Проверка изменения поведения, совместимости, реальных условий исполнения и значимых отказов. |
| `ci-cd-ansible` | Сборка, доставка, инфраструктура и восстановление; правила Ansible подключаются только для Ansible. |
| `prepare-russian-commit` | Сообщение или создание коммита по запросу: одна причина изменения, понятное описание на русском. |

`AGENTS.md` задаёт общий порядок работы и указывает, когда читать каждый навык. Подключать все навыки для каждой правки не требуется. Проектные инструкции определяют фактические инструменты, протоколы, архитектуру и команды проверки.

Проверки выбираются по изменённому контракту и обязательным требованиям навыка. Для каждого изменения исполняемого CI/CD/IaC установлен полный цикл: локальная проверка на чистом состоянии, реальный CI и deploy в тестовое окружение с проверкой результата. Имена сред и команды берутся из проекта; внешние действия выполняются в пределах разрешения пользователя. Для правок только документации или текста навыков проверяются содержимое, ссылки и формат поставки.

## Установка

Источник каталога плагинов: `Seraf-seraf/AGENTS.md`, ветка `main`. Добавьте этот репозиторий как marketplace в поддерживающем его клиенте и установите `backend-engineering`.

- `AGENTS.md` — общие инструкции; подключаются отдельно от плагина.
- `.agents/plugin.json` — манифест и версия плагина.
- `.agents/skills/` — навыки и связанные материалы.
- `.agents/plugins/marketplace.json` — каталог установки из репозитория; корень плагина — `.agents/`.

Для переносимого пакета поместите `plugin.json` и каталог `skills/` из `.agents/` в корень ZIP-архива. Каталог marketplace в этот архив не нужен.

Подключите корневой `AGENTS.md` как общие или проектные инструкции в своей рабочей среде. Установка плагина сама по себе не подключает этот файл. При обновлении сравните его с действующими инструкциями и сохраните собственные дополнения.

## Обновление до 0.2.3

Уточнено, при каких условиях проверка подтверждает работоспособность CI/CD:

- Новый или сокращённый режим подготовки проверяется с чистого состояния, затем запуском потребителя без предварительного полного bootstrap; повторное применение проверяется отдельно.
- Совместимость инструментов подтверждается у всех исполнителей, доступ к ресурсам — из процесса-потребителя. Собственные валидаторы проверяются на реальном выводе используемых версий.
- Готовность целевого окружения подтверждается доступностью обязательных входов; синтетическая конфигурация проверяет только код. Успешный повтор нестабильного теста не закрывает причину падения.
- До коммита и push обязателен локальный этап. Полный цикл завершается подтверждением реального CI, TEST deploy, readiness и основных интеграций для итоговой ревизии и артефакта. Недоступный этап остаётся незавершённым.

Сохранён подход к реализации: Ansible идемпотентно готовит окружение, workflow управляет выпуском, сервис владеет своим конфигом и миграциями. Существующий deployment через Ansible или Helm сохраняется. Ограничение сложности реализации не сокращает проверку её потребителей; новые механизмы добавляются по реальной потребности.

Порядок проверки задан в [CI/CD-навыке](.agents/skills/ci-cd-ansible/SKILL.md), особенности инструментов — в его ссылочных материалах. В [примерах доставки](.agents/skills/ci-cd-ansible/references/delivery-patterns.md) показаны подготовка сервера и выпуск нейтрального сервиса с явными предусловиями. Это ориентиры для выбора решения, а не обязательный каркас проекта.

После получения новой версии исходников обновите каталог и установленный плагин `backend-engineering` до `0.2.3` средствами своего клиента. Отдельно обновите подключённый `AGENTS.md`, сохранив проектные дополнения. Правка репозитория сама по себе не обновляет установленные копии; кеш плагина вручную не редактируется. Имена пакета и навыков не изменились.

### При обновлении с версии до 0.2.1

Имя сокращено с `seraf-backend-engineering` до `backend-engineering`. Обновите подключённый каталог, установите плагин под новым именем и отключите старую копию, чтобы не загружать дублирующиеся навыки. Переименование в репозитории само по себе не переименовывает уже установленный плагин. Если клиент хранит старое имя самого marketplace, переподключите каталог из того же репозитория.

Общие инженерные правила находятся в корневом `AGENTS.md`, специализированные навыки — в плагине. Обновите плагин и подключённый файл инструкций. `.codex/config.toml`, `.codex/rules/allowlist.rules` и `PLUGINS.md` не входят в поставку; собственные настройки клиента сохраняйте. Изменения репозитория не обновляют локальные копии автоматически.
